# 登录与账号权限

当前临时屏蔽启动登录页：`Program.cs` 中 `LoginEnabled = false`，启动后直接以“临时免登录”管理员身份进入主界面，可以使用配置和标定页面。该身份不写入账号库；账号管理仍按真实账号库校验，不能用临时身份新增、重置或删除账号。PLC 站点身份、控制权申请和运动条件检查继续沿用原流程。

恢复登录时，将 `LoginEnabled` 改为 `true` 并重新编译。登录页和已有账号库均保留，恢复后按以下流程使用。

## 使用流程

1. 启动程序先显示登录窗口。没有账号库时，页面提示创建第一个管理员；账号由使用者自行填写，没有内置默认密码。
2. 账号长度 1～32 个字符，忽略前后空格和大小写进行比较；密码长度 8～128 个字符，区分大小写。首次创建需要确认密码。
3. 验证成功后才创建主窗体、启动 Router 和 ADS 连接。退出登录窗口直接结束程序，不启动设备通信。
4. 管理员在主窗体顶部打开“账号管理”，页面显示在主区域，可以新增管理员或操作员、重置选中账号密码、删除选中账号。不能删除当前登录账号或最后一个管理员。
5. 切换使用者时退出程序，重新启动并登录；继续使用已有的通信退出清理流程。

账号管理通过 `NavigateTo` 进入，点击“返回”回到进入前的页面；离开时清除密码输入。监测配置、运行诊断也使用主区域页面。只有启动登录和主窗体继续使用 Form。

## 权限分工

| 功能 | 管理员 | 操作员 |
| --- | --- | --- |
| 账号管理 | 允许 | 禁止 |
| 系统配置 | 允许 | 禁止 |
| 单通道、批量标定 | 允许 | 禁止 |
| 手动控制、控制权申请 | 允许 | 允许 |
| 点位下发、造波操作 | 允许 | 允许 |
| 状态、数据、波形和分析查看 | 允许 | 允许 |

主窗体在按钮和统一的 `NavigateTo → CanOpenPage` 入口检查管理员页面权限。账号管理服务每次操作都会重新读取账号库，独立校验当前账号是否仍为管理员。

软件账号与 PLC 站点身份、PLC 控制权分别管理。登录成功或具有管理员角色不会自动申请控制权；所有设备命令继续经过现有 PLC 授权和运动条件检查。

## 账号保存

- 文件位于当前 Windows 用户的 `%LOCALAPPDATA%\PageSwitching\users.json`，与 ADS 配置、数据库账号分别保存。
- 只保存账号、角色、随机盐和密码哈希，不保存明文密码，日志不记录密码。
- 密码使用 .NET 内置 PBKDF2-SHA256，600000 轮、16 字节随机盐、32 字节哈希；参数参考 [OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2)。
- 保存时先完整写入同目录临时文件，再替换旧库。已有账号库损坏或不可读时停止登录，不自动创建新管理员。
- 账号库属于本地 Windows 用户数据，应随系统配置备份；本功能不替代 Windows 文件访问权限或 PLC 联锁。

## 代码入口与检查

启用登录时，启动链为 `Program → LoginForm → LoginService → Mainpage(LoginUser)`；临时屏蔽时为 `Program → Mainpage(临时免登录身份)`。界面保留独立的 `.Designer.cs` 文件，主窗体仍保留无参构造以支持 Designer。

- `Infrastructure/LoginService.cs`：账号验证、管理员检查和账号库保存。
- `Forms/LoginForm.cs`：登录及首次管理员设置，异步提交共用一个流程。
- `panel/AccountManagementPage.cs`：新增、重置和删除共用一次提交流程。
- `Forms/main_page.cs`：角色入口检查；`PublishMonitorSnapshot` 用同一帧更新两页和顶部状态，保留原有刷新周期。

离线账号检查：`python -m unittest discover -s tests -p verify_login_service.py -v`。

离线界面检查：`python tests/verify_login_ui.py <已编译的 Page switching.dll> <预览图目录>`。检查只使用临时账号，主窗体在设计上下文中创建，不启动 Router 或 PLC 通信。
