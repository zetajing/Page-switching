# 项目架构与源码入口

[文档导航](README.md)

`switch` 是四轴造波设备的 WinForms 上位机。它通过 ADS 读取 TwinCAT PLC 反馈，并向当前站点的命令邮箱提交操作请求。波形生成、浪高采集、分析和数据库同步各有自己的入口。接手项目时，先确认要追的是轴动作、PLC 公布的状态，还是文件和数据处理。

## 工程结构

| 目录 | 职责 |
| --- | --- |
| [Forms](../Forms) / [panel](../panel) | 主窗体、导航、WinForms 功能页及 Designer 布局 |
| [Axis](../Axis) | ADS 控制连接、手动轴、只读反馈、控制权、点位通信与运行统计 |
| [PLC/TwinCAT_NB](../PLC/TwinCAT_NB) | 配套 TwinCAT PLC 源码和离线检查 |
| [Wave](../Wave) | 波形计算、旧程序适配、浪高采集、标定及频谱分析 |
| [Database](../Database) | 本地业务归档和 SQL Server 后台补传 |
| [Infrastructure](../Infrastructure) / [Controls](../Controls) | 配置、日志、账号、Router 及共用 UI 控件 |

上位机目标为 .NET 8 Windows，界面使用 AntdUI，波形绘图使用 ScottPlot。ADS、Router 和 SQL Server 数据存储依赖项目随附的 InduLink DLL。DLL 清单与构建方式见 [lib/README.md](../lib/README.md)。

## 启动、切页和关闭

1. `Program.Main` 创建主窗体。当前 `LoginEnabled = false`，临时免登录身份用于进入软件页面。PLC 站点身份和控制权单独判断。
2. `Mainpage` 读取一次 ADS 配置，创建共享 `AxisService`、独立 `MachineMonitorService` 和各固定页面实例。
3. 窗体显示后先启动或选用 Router。Router 就绪后，监控和手动 ADS 分别连接。手动首次连接失败时每次等待 3 秒再尝试。
4. `NavigateTo` 检查页面权限、记录操作并切换已创建的页面。隐藏页面可暂停自己的刷新，页面输入由原实例保留。
5. 关闭时取消窗体任务，等待已有的停车与采样清理，再释放 ADS 客户端，最后关闭独立 Router。

页布局在 `.Designer.cs`，程序行为写在同名 `.cs`，`.resx` 保存设计器资源。源码入口见 [Program.cs](../Program.cs)、[main_page.cs](../Forms/main_page.cs) 和 [登录与账号权限](登录与账号权限.md)。

## 手动命令如何到达轴

```text
手动页按钮
  → AxisService 的手动命令入口
  → ADS 写当前站的 GVL_control.aStation[站号].aAxis[轴号]
  → PLC 仲裁控制权
  → MAIN 确定本扫描可读取的站号
  → 对应的 FB_AxisCommandGate 取本轴命令
  → FB_AxisControl 调用 NC 运动块并发布实际反馈
```

每个轴对象保存轴号和最近一次快照，四轴共用一个控制连接。控制权、手动写入及部分轨迹通信共用串行锁。PLC 命令门清除交接扫描的旧命令，失联停车按原 PLC 联锁处理。使能是否完成，查看 PLC 的实际使能反馈。[上位机功能分工](上位机功能分工.md) · [TwinCAT 对接](TwinCAT_NB_Integration.md) · [三站控制权](ControlAuthorityRules.md)

## PLC 反馈在哪里读取

`FB_HmiFeedback` 在四个基础轴块运行后发布 `GVL_HMI.stMonitor`。C# 的 `PlcMachineMonitor` 对应布局版本 4、164 字节。手动页和机器监控各用自己的连接读取同一个 PLC 符号。

| 用途 | 读取入口 | 结果 |
| --- | --- | --- |
| 手动页四轴显示 | `AxisService.ReadSnapshotAsync` | 一次整帧读取，校验布局后直接生成四轴快照 |
| 顶部状态、造波页与控制权页 | `MachineMonitorService.RefreshAsync` | 一次整帧读取，确认心跳变化和时效后发布只读快照 |
| 运行诊断 | `AxisService.ReadDiagnosticsAsync` | 手动请求时读取监控帧及四轴参数 |
| 运行实测统计 | `AdsAxisMonitoringSource.ReadAsync` | 对本软件发起的轨迹独立采集位置、速度和反馈质量 |

独立监控遇到连接错误时按自己的间隔重试。手动连接的运行期恢复限制、符号排查和断点入口见 [ADS 连接](AdsConnectionGuide.md)、[监控接口](PlcMonitoringContract.md)、[代码调试](CodeSimplification.md)。

## 波形生成、点位文件和设备执行

| 工作 | 程序入口 | 产物 |
| --- | --- | --- |
| 规则波或不规则波生成 | [WaveformPage](../panel/waveform.cs)、[WaveformGeneratorService](../Wave/Generation/WaveformGeneratorService.cs) | 内置 WaveMaker 的水面高程 CSV，或 WFast / WP-5-6 对应的外部方案输出 |
| 自定义谱 | [CustomSpectrumPage](../panel/CustomSpectrumPage.cs) | 校验频率/谱密度两列，调用 WP-7 生成旧格式信号 |
| 读取最终轴点位 | [WaveTrajectoryFile](../Wave/Legacy/WaveTrajectoryFile.cs) | 将旧格式的 2 ms 点位直接导入，或将 20 ms 点位插值为 2 ms，保留首尾与总时长 |
| 导入、预检、发送和启停 | [Auto 的造波入口](../panel/auto.Wave.cs)、[点位下发服务](../Axis/PointUpload/AxisService.PointUpload.cs) | 上位机按 PLC 四轴参数预检，通过后分段发送，由 PLC 确认拼表和运行状态 |

内置生成的 `TimeSeconds,ElevationMetres` 是水面高程。摇板角度、丝杆位置、PLC 轴点位之间的转换依赖实机几何和轴单位。执行流程、协议和设备参数分别见 [造波页操作](WaveOperation.md) 和 [造波计算记录](WaveGenerationNotes.md)。

## 浪高仪、标定和分析

1. 浪高仪使用独立 TCP 客户端。`WaveHeightMeterClient` 缓存接收数据，把完整帧交给 `LegacyChannelOneProtocol`。当前实采只支持 CH1，帧长 15 字节，帧头为 `AA 55 55 AA`，CH1 原始值取帧末两个字节的大端整数。CH2–6 可用于历史文件和人工标定，设备协议仍待确认。[TCP 客户端](../Wave/Acquisition/WaveHeightMeterClient.cs) · [帧协议](../Wave/Acquisition/WaveHeightProtocol.cs)
2. `WaveDataWorkspace` 管理会话、CSV 和标定。水位计算采用 `(RawCount - ZeroRawCount) × Slope + Intercept`。采集中保持本次标定版本，缺少有效标定时保留原始计数。[采集工作区](../Wave/Acquisition/WaveDataWorkspace.cs) · [单通道标定](../panel/Calibration.cs) · [批量标定](../panel/WaveBatchCalibrationPage.cs)
3. 数据管理从 `session.json` 筛选会话，以 CSV 查看和导出采样值，支持导入旧采集文件。按单通道导出时附带会话元信息，供后续分析使用。[数据管理](../panel/Data.cs)
4. `WaveSeriesFile` 将当前采集 CSV、生成高程 CSV 或旧采集文件读为通道、水位数组和采样间隔。内置分析使用去均值、Hann 窗、FFT 单边谱和上跨零统计。旧分析调用 WaveTJU，频谱和要素均可导出。[序列读取](../Wave/Analysis/WaveSeriesFile.cs) · [内置分析](../Wave/Analysis/WaveAnalysisService.cs) · [分析页面](../panel/WaveAnalysisPage.cs)
5. 信号修正页面读取旧位移信号和实测水位，转换为 WC-12 所需文件，再比较原信号与修正输出。旧程序按任务使用独立工作目录。[信号修正](../panel/SignalCorrectionPage.cs) · [旧程序执行器](../Wave/Legacy/LegacyProgramRunner.cs)

## 配置、日志和数据文件

| 运行目录中的位置 | 内容 |
| --- | --- |
| `Page switching.dll.config` | 运行设置，源码默认值来自 `App.config`。ADS 设置重启后应用 |
| `Operations/` | 默认操作日志位置，每小时一个文件 |
| `users.json` | 本机账号库 |
| `WaveHeight/` | 标定、采集 CSV 和会话 JSON |
| `AxisMonitoringSettings.json`、`AxisMonitoring/` | 运行统计阈值、采样和报告 |
| `WavePrograms/` | 旧程序任务工作目录、分析输出 |
| `DatabaseArchive/` | 操作、轨迹、运行归档及同步游标 |

`OperationJournal` 统一记录页面操作和结果。`DatabaseArchive` 先保存本地记录，`DatabaseSyncService` 再独立补传至 SQL Server，可同步点位块、传感器明细及轴采样。此前的 `WaveCaptureSessions` 属于旧索引，现行表和补传规则以 [数据库保存与补传](DatabasePersistence.md) 为准。[操作日志](../Infrastructure/OperationJournal.cs) · [数据库同步](../Database/DatabaseSyncService.cs)
