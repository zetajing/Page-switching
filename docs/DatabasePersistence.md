# 数据库保存与补传

更新：2026-10-29。数据库提供程序来自用户的 `C:\Users\75881\Desktop\total`，源码和PLC控制逻辑分别维护。

## 从哪里使用

1. 管理员进入“系统配置 → SQL Server 数据保存”，勾选启用，填写已有SQL Server服务器和数据库。账号为空时沿用连接字符串中的Windows身份等设置；填写SQL账号后会写入连接字符串。
2. 点击“连接并建表”，检查连接并初始化8张业务表。程序不创建数据库本身，需要先有数据库和适当权限。
3. 点击“保存数据库”。后台每5秒尝试补传，设置保存后即被下次同步读取。未启用时仍保存本地文件。
4. 从“数据管理 → 数据库记录”查看记录或立即同步。管理员和操作员均可查看、导出；查询页没有删除和编辑入口。

连接配置仍使用现有 `DatabaseEnabled`、`DatabaseConnectionString`、`DatabaseUserName`、`DatabasePassword`。初始保持关闭；配置中的数据库账号与软件登录账号是两套账号。配置保存方式沿用现有App.config机制，不改变PLC连接参数。

## 保存内容

| 页面类型 | SQL Server表（dbo） | 内容与查询任务编号 |
| --- | --- | --- |
| 操作日志 | WaveOperationHistory | 时间、登录用户、站点、页面、消息、RunId；可按RunId查关联操作 |
| 造波文件 | WaveFileHistory | DataId、首次归档文件名、点数、2ms周期、创建时间；按DataId查询 |
| 目标点位 | WavePointBlocks | 实际预检/下发的double数组，1000点一块；按DataId查询 |
| 造波运行 | WaveRunHistory | RunId、DataId、MonitorRunId、操作者、站点、上传序号、请求/准备开始及结束时间、状态与错误；按RunId查询 |
| 轴实际反馈 | WaveAxisHistory | 已有100ms监测CSV中的读取时间、耗时、心跳、序号、所属站、质量及四轴位置/速度；按MonitorRunId查询 |
| 传感器任务 | WaveSensorSessionHistory | SessionId、RunId、设备、通道、频率、标定版本、样本数、本地路径、旧文件导入标记；按SessionId查询 |
| 传感器数据 | WaveSensorHistory | 每条原始计数、标定值、时间、通道、标定版本；按SessionId查询 |
| 超限报告 | WaveMonitorReports | 原有监测汇总及阈值快照；按MonitorRunId查询 |

所有表由 `InduLink.Storage.dll` 创建，使用SDK通用历史结构。业务字段在 `ValueText` 中保存为JSON；目标点位的 `RawData` 为Windows小端double二进制，`ValueText` 标明块起点、数量和周期。一次DLL写入最多200条记录，每条点位块最多1000点；没有把整场传感器数据读入DataTable后再入库。

DataId按本机归档来源及点位内容计算。同一来源的相同点位复用归档；不同电脑来源隔离，避免两个站同时补传覆盖同一批。四轴当前共用一份目标点位，保存的是该点位数组，不伪造四份独立指令。RunId每次启动请求新建；上传失败后未启动，不创建“已运行”记录。

Run记录的开始时间包括使能和必要回原，不能当作PLC正式运动时间。正式执行的采样范围仍由原有监测服务确定。轴反馈仅同步原监测服务已生成的CSV，没有新增运动控制或ADS写入；监测未配置时不会伪造反馈样本。缺测、NaN和无穷值保留原因/质量并将相应值写为JSON null。

传感器采集开始时，若本机已有造波RunId便自动关联；独立采集或先采集后启动时RunId为空，可按时间查阅。旧文件导入仍标记为导入，不当作本次实采。CH2–6仍未启用实采。

## 本地文件与补传

本机数据库归档目录：`%LOCALAPPDATA%/PageSwitching/DatabaseArchive/`。

```text
operations/  每小时JSONL日志，固定记录ID
waves/       点位二进制和元信息
runs/        每次启动请求的运行JSON
sync/        按目标服务器、数据库区分的同步游标
```

原有 `Operations` 日志、`WaveHeight` 传感器CSV和任务JSON、`AxisMonitoring` 轴采样CSV和报告均保留。传感器和监测文件在结束后补传，运行记录在状态更新后补传；正在追加的日志按已读取行数推进。数据库自身故障消息只写原日志，避免数据库失败再生成入库失败消息的循环。退出后的最后日志在下次启动时补传。

后台同步和手动同步共用一把独立锁，不使用运动命令锁。SQL连接超时3秒，单条命令超时10秒；软件退出取消同步并最多等待后台任务2秒。SQL或文件异常只更新数据库诊断，不覆盖运动故障、停车结果，不发停止或启动命令。

SDK目前没有按业务键原子更新接口，因此固定批次采用“删除同批 → 事务写入 → 保存本地游标”。删除和写入是两个事务，**失败或重试期间该批数据可能暂缺**；提交后应答丢失时也会重放该批，以免重复。同步完成前不能把查询结果视为完整归档。游标丢失会重建该来源日志；更换服务器或数据库会独立重放，修改密码不会强制重放。

当前按每个本地归档目录单一运行实例设计；不支持两个程序实例同时写同一归档目录。未配置自动清理/保留期限；本地归档和数据库容量需要按实际采样量管理。异常关闭时未取得结束反馈的运行保留空结束时间，不推断为正常完成。旧 `WaveCaptureSessions` 索引表保留；有本地CSV的旧任务会补传到新表，只有旧SQL索引而没有本地文件的历史不会自动还原。

## 查询和导出边界

时间按本地输入转换为带时区时间。一般类型每次最多查询最近500条；目标点位预览只展开查询到的1个块，最多1000点。任务编号可留空；有连字符的GUID会自动转成归档使用的无连字符形式。

“导出当前结果”只导出表格当前记录，明确不等同于完整数据库备份或整场数据导出。传感器整场CSV及轴监测原始CSV继续在原有目录。若需要数百万点分页检索、全量数据库导出或长期保留策略，应作为后续独立功能。

## 代码阅读入口

- `DatabaseArchive`：创建本地日志/点位/运行归档，无SQL。
- `DatabaseRows`：顺序解析传感器、轴监测CSV，支持引号和换行。
- `DatabaseStore`：把业务数据转换成Total的 `InduLinkDataRecord`，调用DLL建表/写入/查询。
- `DatabaseSyncService`：单后台循环，补传本地文件、更新游标及同步状态。
- `DatabasePage`：只读查询、导出当前结果；布局在Designer。
