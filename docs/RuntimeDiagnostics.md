# 运行诊断与四轴参数

本轮对应“项目优化路线”的第一批：保留首次故障、识别配套版本、集中查看轴参数、复制诊断。整表点位检查仍由上位机负责，PLC 不恢复整表数值扫描。

## 从哪里查看

在“控制权申请”页面点击“运行诊断 / 轴参数”。窗口独立显示，主窗体的停止入口仍可操作；查看不要求持有 PLC 控制权，管理员和操作员都可以查看。

点击“读取诊断”只读取 `GVL_HMI.stMonitor` 和四轴 `GVL_motion.aConfig[1..4]`，不会申请控制权、修改轴配置或发送运动命令。状态和参数分次读取，页面显示读取完成时间；这是一份手动快照，不能据此确认心跳持续更新或设备当前停稳。主页面继续使用原有周期监控和新鲜度判断。

参数表显示最小/最大位置、最大速度/加速度、停车减速度、到位容差和首点定位速度。参数由 `FB_AxisConfig` 填写，窗口只读；读取失败会清空旧参数并显示具体符号错误，不用零值代替。位置、速度和加速度都使用 PLC/NC 原始单位，不推断角度与丝杆位移的换算。

“复制本次诊断”复制窗口中的同一份状态、版本、四轴参数及最近一次造波操作失败记录。复制过程不重新访问 PLC。上位机最近一次原始失败单独保留，后续停车或成功操作不清除；窗口关闭后再次打开也可从当前服务取得，程序重启后通过操作日志追溯。

## 首次故障与停车结果

`GVL_motion.udiErrorId` 保留首次故障码。新增 `nFaultAxis`、`nFaultSource`、`nFaultState` 分别记录轴号、来源和发生阶段；有效组复位时一起清除。多个轴在同一扫描出错时，按轴号1到4保留第一项，不在四轴 MC 调用循环中途切换公共状态。

停车、关闭外部给定或退出超时的第一个错误保存在 `udiCleanupErrorId`，不能覆盖已有首因。如果此前没有轨迹错误，清理阶段错误本身成为首次故障。清理错误为0只表示尚未报告清理错误，不能代替 `xAxesStopped` / `xAxesIdle` 的实际确认。退出超时仍保持占用，不强制清 Busy。

| 来源码 | 含义 |
| --- | --- |
| 0 | 组条件或未标识来源，核对原始错误码 |
| 1 / 2 / 3 | 运行许可丢失 / 控制权失效 / 撤使能或使能反馈丢失 |
| 4 / 5 / 6 | 单轴停止 / 点动回原复位冲突 / 软硬限位 |
| 7 / 8 / 9 | 心跳超时 / 轴错误或I/O无效 / 外部给定意外退出 |
| 10 / 11 | 首点MC_MoveAbsolute / MC_ExtSetPointGenEnable |
| 12 / 13 / 14 | MC_Stop / MC_ExtSetPointGenDisable / 等待退出超时 |
| 15 / 16 | 轴参数检查 / 就绪或首点到位检查 |
| 17 / 18 | 收段拼表或启动元数据 / 拼表内存复制 |
| 19 / 20 | 首点定位超时 / 开启外部给定超时 |

轴号0表示组条件或尚未定位到单轴，不猜测具体轴号。轴参数、NC故障和首点MC错误会记录对应轴；MC原始错误号同时以十进制和十六进制显示。

## 配套版本

当前监控布局为 **4 / 164字节**，接口行为版本为 **1**，PLC源码发布号为 **2026102401**（第五项内部整理，前版2026102301）。新增字段和偏移见[监控契约](PlcMonitoringContract.md)。上位机显示程序集版本，从Git工作目录构建时附带提交号；PLC发布号是源码中的发布标识，不能代替实际构建结果或全部源码差异检查。

反馈读取检查布局；点位下发和开始准备前另检查行为版本，开始沿之前再次检查。行为版本不匹配时不能清表、下发点位、自动使能或启动；停止流程保持独立。旧监控布局会被拒绝，因此上位机和PLC必须成套更新。版本检查不是ADS访问控制，也不能证明其它客户端执行过预检。
