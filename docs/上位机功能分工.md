# 上位机功能分工与调试入口

上位机按“反馈读取、手动控制、控制权、点位下发”分目录，轨迹会话与运行单独保留。`AxisService.cs` 管理共享连接、四个固定轴对象和资源释放，各功能实现放在对应的分部文件中。

分部文件仍属于同一个 `AxisService`，共用 ADS 写连接和串行锁。页面不需要自行管理新的通信服务，方法名、配置和调用关系保持兼容。

| 功能 | 代码入口 | 职责 |
| --- | --- | --- |
| 共享连接 | `Axis/AxisService.cs` | Connect、Disconnect、GetAxis、Dispose；保存连接及公共状态 |
| 反馈读取 | `Axis/Feedback/AxisService.Feedback.cs` | 手动页整帧读取、失败时标记不可用、更新四轴 Snapshot |
| 机器监控 | `Axis/Feedback/MachineMonitorService.cs` | 主窗体的独立只读连接；监控帧、心跳有效性、过期和重连 |
| 手动控制 | `Axis/ManualControl/AxisService.Manual.cs` | 单轴和全轴使能、报警复位、回零、停止、点动 |
| 单轴入口 | `Axis/ManualControl/Axis.cs` | 轴号、最新快照和该轴的命令入口；四根轴共用同一服务 |
| 控制权 | `Axis/ControlAuthority/AxisService.Authority.cs` | 本站心跳、申请、释放及同序号应答；连接成功不代表已授权 |
| 点位下发 | `Axis/PointUpload/AxisService.PointUpload.cs` | 复制输入点位、读取 PLC 四轴参数并预检，合格后下发、确认及拼表；启动前核对参数 |
| 点位预检 | `Wave/Legacy/WavePointValidator.cs` | 检查首尾、数值、位置/速度/加速度及停车空间，报告轴、点号、实际值和限值 |
| 下发分批 | `Axis/PointUpload/WaveTransferChunks.cs` | 将逻辑段划分为有界 ADS 小批次，不跨段、不串轴 |
| 轨迹会话 | `Axis/Trajectory/AxisService.WaveSession.cs` | 后台任务、会话锁/心跳确认、原始失败和清理；保存同一组共享状态 |
| 轨迹运行 | `Axis/Trajectory/AxisService.Trajectory.cs` | 核对本次表、准备四轴、启动并等待完成 |
| 轨迹停止 | `Axis/Trajectory/AxisService.WaveStop.cs` | 取消旧任务、实际停稳确认、释放停止位和退出 |
| 轨迹通信 | `Axis/Trajectory/AxisService.WaveCommunication.cs` | 原有 ADS 读写、脉冲、反馈心跳及条件等待，不另建连接 |
| 故障说明 | `Axis/Feedback/PlcWaveDiagnostics.cs` | 将 PLC 轨迹状态和故障码转为中文说明；格式化失败时的只读反馈，不增加 ADS 请求 |

## 从页面跟到代码

- 软件登录：`Program → LoginForm → LoginService → Mainpage(LoginUser)`。账号和角色独立于 PLC 控制权，具体使用见[登录与账号权限](登录与账号权限.md)。
- 查看手动状态：`Manual.RefreshValuesAsync → AxisService.ReadSnapshotAsync → ReadAdsSnapshotsAsync → UpdateAxisSnapshots`。这条读取链不要求控制权，也不写使能、复位或申请请求。
- 查看机器状态：`Mainpage.RefreshMonitorAsync → MachineMonitorService.RefreshAsync`。保留现有独立监控连接和调度，不占用手动命令的串行锁。
- 单轴手动：`Manual.SelectedAxis → Axis.HomeAsync / JogAsync / StopAsync → AxisService.Manual.cs`。所有命令仍检查现有授权与会话条件。
- 控制权操作：`ControlAuthority → ChangeControlAuthorityAsync`。先写动作，再提交序号，等待 PLC 同序号确认；请求写成功不等于授权成功。
- 下发点位：`UploadWaveAsync → UploadWaveCoreAsync → 写独立段 → xUpload 登记 → 等待段确认 → xAssemble 拼表 → 等待 Ready`。下发完成不调用启动。
- 启动轨迹：`StartWaveAsync → StartWaveCoreAsync → PrepareWaveAxesAsync → ExecuteWaveAsync`，分别用于核对本次表、准备四轴、启动并等待退出。停止仍通过 `StopWaveAsync`。

排查问题的断点、变量和日志入口见[代码阅读与调试入口](CodeSimplification.md)。整表数值检查由上位机在下发前完成；PLC 状态 10 保留配置和轴就绪检查，运行及停止流程保持原样。

2026-10-24 内部整理后的完整调用图、PLC Action 顺序和变量保留理由见[第五项整理记录](Step5CodeMap.md)。

## 本轮整理的边界

本轮只迁移职责对应的原有字段和方法，保留方法体、ADS 符号、写入顺序、心跳周期、锁与取消流程。机器监控和手动反馈仍使用各自原有的读取调度，两个读取入口都放在 Feedback 中。

自动造波计算、轨迹运行给定、页面布局、Designer 文件、统一页面切换与主窗体日志入口保持现状。PLC 侧继续使用六个 Action；仅将整表数值校验迁移到上位机，没有放宽运动联锁。
