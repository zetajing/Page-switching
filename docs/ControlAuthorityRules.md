# 三站控制权与运行锁

[返回文档导航](README.md)

用户确认的优先级为：**造波控制室 > 拖车本地 > 远程操作室**。

2026-10-15 新增约束：**设备运行中禁止控制权交接，包括高优先级接管和当前站主动释放。** 高优先级申请不会为让权而强迫当前运行停车。运行中拒绝的请求立即应答，不排队到停机后自动执行；停稳后必须重新申请。

## 配套 PLC 协议

这是本次新增的配套协议，必须与 `PLC/TwinCAT_NB` 一起部署，不能直接套用到尚未升级的旧 PLC。

| 编码 | 本站身份设置 | 控制站 |
| --- | --- | --- |
| 0 | 空/未配置 | 未分配，不允许写轴命令 |
| 1 | WaveControlRoom | 造波控制室，最高优先级 |
| 2 | TowingLocal | 拖车本地 |
| 3 | RemoteControlRoom | 远程操作室 |

本站身份在启动时锁存，配置保存后重启生效。选择身份不等于取得 PLC 授权；每个站点身份应只运行一个命令客户端。

控制权采用纯软件申请，不依赖现场主控选择或授权开关。三个站均可提交申请，PLC 独立检查本站心跳、运行锁及优先级：

- 无持有者且设备未运行时，任一在线站可申请。
- 已有持有者且设备未运行时，只有更高优先级站可接管；本持有者重复申请确认现有权限。
- 运行中拒绝其他站接管和当前站释放；本持有者重复申请不改变控制权。
- 没有新申请不会自动选站；被拒绝的请求不排队，停稳后须重新申请。

旧版 `xCenterMaster`、`xLocalMaster`、`xAllowLocal`、`xAllowRemote` 已移除，不应再通过写入这些变量取得申请资格。上位机和 PLC 应配套更新；新版页面收到旧版结果码 3 时提示更新 PLC。

## 请求与应答

每站邮箱为 `GVL_control.aStation[1..3]`：

| 字段 | 写入端 | 语义 |
| --- | --- | --- |
| udiHeartbeat | 本站 | 每 250 ms 改变，PLC 3 秒不变判失联 |
| nAction | 本站 | 1 申请；2 释放 |
| udiRequestSequence | 本站 | 最后提交的新非零序号 |
| udiAckSequence | PLC | 已处理序号；拒绝也应答，不保留待接管请求 |
| nResult | PLC | 同序号结果，见下表 |
| xOnline / xGranted | PLC | 心跳有效 / 本站实际命令许可 |
| xWaveSession | 本站 | 发送、准备和执行会话锁，失联后忽略旧保持位 |
| aAxis[1..4] | 本站 | 四轴命令：使能、点动、回原、复位、停止和点动速度 |

| nResult | 含义 |
| --- | --- |
| 1 | 成功；本持有者重复申请只确认现有权限，不发生交接 |
| 2 | 统一交接锁有效，拒绝本次操作 |
| 3 | 保留：旧版现场授权拒绝，新版 PLC 不再返回 |
| 4 | 本站心跳未建立或已超时 |
| 5 | 非持有者不能释放 |
| 6 | 当前由更高优先级站持有 |
| 7 | 无效站点或操作 |

上位机先写动作，最后提交序号，等待相同序号应答和实际 Owner/Granted 确认。5 秒无确认提示结果不确定，不自动重试或显示授权成功。

## PLC 控制规则

`FB_ControlAuthority` 只保留一份交接锁 `xLocked`，申请、释放和失联退出都使用它：

- 有运动、轨迹占用、轴块 Busy 或待执行的点动/回原/造波命令时，禁止交接。
- 空闲时可申请或释放；接管仍按造波控制室、拖车本地、远程操作室的优先级执行。
- 持有站失联后先撤销命令许可；退出条件满足后清 Owner 和旧命令。恢复心跳必须重新申请。

NC I/O 无效单独发布为 `xFeedbackInvalid`。它本身不阻止申请和释放；I/O 无效且轴仍使能时，统一交接锁保持有效。基础轴块始终禁止 I/O 无效下的新使能和运动，复位沿用原有入口。取得控制权不表示设备具备运动条件。

`nOwner` 由 PLC 私有变量维护，GVL 中只是反馈。`FB_AxisCommandGate` 只复制已授权站的邮箱命令；交接扫描清空所有站旧命令并阻断执行，新持有站必须重新下发操作。没有新请求不会自动选站，被拒绝的请求不会在空闲后自动重放。

## 上位机与工程路径

申请和释放按钮使用同一份 `xLocked`；持有站可释放，其他站可申请。页面只显示授权状态、忙碌提示和 I/O 故障。连接、心跳、请求序号应答及 5 秒确认超时保持原协议。

上位机读取 Owner、xLocked、本站 Granted/AckSequence/Result 和 xFeedbackInvalid，共六项。`xCanRelease` 留在 PLC 中兼容已有客户端，由 Owner 和 xLocked 推导，不再有独立释放锁。监控结构体布局不变。

当前统一解决方案 `Page switching.sln` 引用 `..\PLC\TwinCAT_NB\TwinCAT_NB.tsproj`。修改必须同步到该实际工程，仓库内 `PLC/TwinCAT_NB` 保存 Git 交付副本。

## 验证边界

离线检查执行实际 `F_ControlDecision`、完整 `FB_ControlAuthority` ST 和基础轴联锁条件。覆盖三站优先级、运行中拒绝交接、I/O 故障下空闲申请/释放、连续失联重连、清旧命令和拒绝请求不重放。TON 使用离散时钟替身，不连接实际 ADS 或 NC。
