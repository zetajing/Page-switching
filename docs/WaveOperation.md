# 造波页操作与通信

[返回文档导航](README.md)

本功能只执行已确认的最终 PLC 轴点位，不生成、缩放或换算波形，不启用主动吸收。导入一套点位后，四轴使用完全相同的位置表，周期固定为 2 ms。

## 四个按钮

1. 导入造波信号：选择旧格式 CSV/TXT/DAT，首行为表头，其后为 8 行元信息，再后为声明数量的位置行。点数 4～2,100,000，周期必须为 0.002 秒，第一列必须为有限数值。第二列忽略，水面高程文件拒绝。失败保留上一次文件。
2. 发送造波信号：本站先取得控制权，确认轴已停稳、基础块空闲且 NC 反馈有效；允许轴处于未使能 Disabled 状态，无需先使能或回原。服务读取 PLC 四轴参数并在上位机检查整表；失败时显示轴号、点号、时间、项目、实际值和限值，不清旧表、不下发任何点位。合格后才清旧接收状态，采用新的非零轨迹序号逐段下发；每段四轴全部写完才登记并等 PLC 确认。全部下发后单独请求拼表，确认 DataReady 和累计点数、序号、所属站一致才显示已发送。不会自动运动。
3. 开始造波：要求本文件已发送，PLC 联锁、参数及反馈有效，无轴报警。按钮不可用时，详情区逐项列出“暂不能开始”的原因。准备前重读四轴参数，与本次下发预检时逐项比较；变化时拒绝开始并要求重新下发。自动清旧点动/回原/停止请求、保持四轴使能；10 秒内等使能成功，仅对未回原的轴发回原请求，120 秒内等四轴回原且运动块退出；发启动沿前再核对一次参数。PLC 仅检查表完整性、配置和启动就绪，再首点定位和执行，不再逐点校验整表。NC 回原方式、速度、原点传感器仍由现场配置提供。
4. 停止造波：取消本服务正在预检、发送或准备的任务，禁止迟到写入继续启动。PLC 取消收段/拼表/启动检查或从当前位置减速退出；回原由基础块停止。先等实际停稳，再释放停止位、等 MC_Stop 退出，最后显示已停止。正常人工停止不报通用 1007 故障，真实轴故障和联锁仍保持故障。

发送、准备、执行期间禁止更换文件、重复启动和手动操作，停止入口独立可用。本站没有有效控制权时只能本地导入和读取反馈。自然完成或停止后，下次运行必须重新发送；不循环、不重放旧序号、不自动重试运动命令。页面切换不停止已运行轨迹；程序退出先取消并尝试停车，再释放服务。

## 上位机点位预检

`ReadWaveAxisLimitsAsync` 只读 `GVL_motion.aConfig[1..4]` 的七项实际 LREAL 参数；读取失败、质量无效或参数不合格均拒绝发送，不用本地默认值代替。`WavePointValidator.Validate` 对四轴共用的最终点位按每轴各自限制检查：首两点/末两点相等、数值有限、位置范围、中心差分速度和加速度、相邻点增量、预计停车位置。公式与原 PLC 一致，周期 0.002 秒，不放宽浮点阈值，不缩放、限幅或重采样原文件。

失败点号从 0 开始，并显示 `时间=点号×0.002 秒`。停车估计仍为 `p+v×|v|/(2d)+v×0.002`，不包含实际跟随误差、驱动延迟或额外安全余量。PLC 仍负责实际运行时的权限、心跳、限位、反馈故障、联停、首点到位和 MC 错误；数值预检与实际运行联锁职责分开。

新 PLC 必须配套带预检功能的上位机使用；其他 ADS 客户端也须在写表前执行同等检查。当前配套监控接口为版本4/164字节，下发与启动另外要求接口行为版本1；PLC 不新增整表数值预检变量。

## 虚拟轴调试参数

轴配置单独放在 `POUs/AxisConfig_轴配置/FB_AxisConfig`。需要调整数值时，直接修改这个块末尾的七条 `GVL_motion.aConfig[i]` 赋值；手动控制、监控和轨迹读取同一份全局配置，不经过模板复制。

`MAIN` 先调用 `A01_ReadAxisStatus()` 和 `A02_ControlAuthority()` 刷新状态，再调用 `fbAxisConfig()`。配置块只保留一个循环序号 `i`，直接读取现有的空闲、反馈有效和运动锁状态，并直接确认四轴当前停稳及速度有效。条件满足时直接应用本块的七项参数，已有旧值也会更新；运动、停止、拼表或待释放的点动/回原/轨迹启动请求存在时保持原值。

当前四轴使用以下虚拟轴调试初值，数值单位跟随 NC；它们不是已确认的实机参数：

| 参数 | 初值 |
| --- | ---: |
| 最小位置 / 最大位置 | -200 / 200 |
| 最大速度 | 200 |
| 最大加速度 | 12000 |
| 停车减速度 | 100 |
| 首点定位速度 `lrInitVelocity` | 10 |
| 到位容差 `lrStartTolerance` | 10 |

在线更改可能保留已有全局变量值，因此本块在空闲时显式赋值，不依赖数组声明初值，也不另设初始化标志。配置的唯一填写处是本块：在线直接改数组会在后续空闲扫描被块内数值恢复；需要调整参数时修改本块。更新 PLC 后核对四轴 `GVL_motion.aConfig` 的实际值。[Beckhoff 在线更改说明](https://infosys.beckhoff.com/content/1033/tc3_plc_intro/2528041355.html)

这是当前虚拟轴调试用的初始化块。接实机时应取消这处调试初始化调用，改用已确认的设备参数和配置流程。

本次虚拟轴排查中，`2222_2ms_327.66s.csv` 的 163831 点按现有差分式计算，峰值速度约 189、峰值加速度约 11250；旧的 100/100 限值在第 270 号点首次因加速度约 -250 报 1003。用户确认仅为虚拟轴将上限调整到 200/12000，保留原文件、2 ms 周期及 327.660 秒时长。停车减速度仍为 100；这些调试限值不能当作实机运动能力。

重新启动上位机后，本地上传资格不会恢复；需要重新申请有效控制权、导入并发送点位，等 PLC 拼接完成再开始。开始前显示“手动”模式是正常状态，模式反馈不是启动的前置条件。

## 数据和权限

- 反馈地址只有 AdsMonitorSnapshot=GVL_HMI.stMonitor，版本 4 / 164 字节；手动页、机器监控和造波服务复用同一结构定义。
- ST_ControlStation 增加 xWaveSession，会话期间阻止接管/释放；站点失联后撤命令停车，实际运动锁仍独立有效。
- GVL_motion.nCommandStation 是命令来源号，必须匹配当前有效 Owner。PLC 锁存 nUploadStation，控制端变化或失联使旧表失去启动资格。它属于应用协议，不代替 ADS 访问权限。
- GVL_motion.aUpload 仍是 21 段 × 4 轴 × 每轴 100000 点；以小批次最多 1024 点通过 DLL WriteManyAsync 写标量符号。DLL 的 WriteArrayAsync 只能写尺寸匹配的完整数组，不能把某个 LREAL 符号当作数组切片。
- 每批释放共享 ADS 门锁，停止和心跳可穿插。发送遇到任何写入或确认失败立即中止，不把部分成功当成完整接收。
- 本站心跳约 250 ms 更新；造波会话期间同时更新轨迹心跳；PLC 自己约 500 ms 更新反馈心跳。造波服务检查反馈心跳变化，停止不确定时暂停本站心跳，让 PLC 独立失联停车；确认停稳后重启上位机恢复，不自动重连续跑。
- 明确重发时可单次清组故障后重新清表，不反复复位，也不自动复位各轴报警。

## 监控布局扩展

前 104 字节的四轴反馈顺序不变，布局版本升级为 4。尾部按顺序：nTrajectoryState(UINT)，nReceivedCount、nLoadedCount、nPointCount、nCurrentPoint、udiReceivedSequence、udiAcceptedSequence、udiErrorId(7×UDINT)，nUploadStation(UINT)，以及 xUploadBusy、xDataReady、xTrajectoryBusy、xRunning、xDone、xError、xStopped、xMotionPermit、xConfigValid、xAxesIdle、xAxisFault、xAxesStopped(12×BOOL)。再追加程序版本(UDINT)、接口行为版本/首次故障轴/来源/阶段(4×UINT)、停车退出错误(UDINT)，总长 164 字节，双方 Pack=1。xAxesStopped 用于停稳确认，xAxesIdle 还要求停止等异步块释放，不能混用。
