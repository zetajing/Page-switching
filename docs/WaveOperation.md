# 造波文件、下发和启停

[文档导航](README.md)

造波页执行已确认的最终 PLC 轴点位。四轴共用同一份位置曲线，分别按自身实际参数预检。当前点位周期为 2 ms，位置和速度使用 PLC/NC 原始单位。内置 WaveMaker 的水面高程 CSV 需要另行完成设备转换才可用于执行。见 [造波计算记录](WaveGenerationNotes.md)。

## 操作顺序

| 操作 | 前置条件 | 成功依据 |
| --- | --- | --- |
| 导入造波信号 | 选择旧格式点位文件，校验行数、周期和有限数值 | 页面显示原始点数/周期、下发点数/周期和时长 |
| 发送造波信号 | 本站有有效控制权，四轴停稳、轴块空闲、NC 反馈有效。允许轴处于未使能状态 | 完成预检、分段接收和拼表，PLC 回报 `DataReady`，点数、序号和所属站匹配 |
| 开始造波 | 本次文件已发送，控制权、参数、运行许可与反馈有效，轴无报警 | 人工确认后重新检查 PLC，准备四轴，再提交启动。进度来自 PLC 的执行反馈 |
| 停止造波 | 已进入预检、下发、准备或执行 | 取消在途任务，PLC 取消未执行流程或减速退出。上位机确认实际停稳、释放停止请求，再等待运动块退出 |

开始有确认窗口，默认选择取消。准备阶段先读取实际参数并与下发时的预检参数比较，清除旧手动请求后保持四轴使能。使能等待上限 10 秒，回原等待上限 120 秒，只对尚未回原的轴发请求。提交启动前再核对参数。参数变化后需重新发送，实际能否启动由 PLC 联锁判定。

发送、准备和执行期间，界面阻止换文件、重复启动和手动运动，停止入口独立可用。自然完成、停止或上位机重启后，下次运行需重新发送。没有控制权时仍可在本地导入和查看反馈。切换页面不会取消正在运行的会话。

## 文件格式和整表预检

- CSV、TXT 和 DAT 采用旧点位格式。第一行为表头，随后 8 行元信息，再读取声明数量的点位行。第一列为有限位置值，第二列不用于执行。原始文件至少 4 点，失败时保留此前导入结果。
- 2 ms 文件最多 2,100,000 点。20 ms 文件最多 210,000 个原始点，按相邻两点间的直线插值成 2 ms。输出点数为 `(原始点数 - 1) × 10 + 1`，原点、首尾及总时长保留，原文件不改。
- 发送前读取 `GVL_motion.aConfig[1..4]` 的七项 LREAL 参数。参数读取或质量错误时拒绝发送。每轴预检首两点和末两点是否静止、位置范围、中心差分速度/加速度、相邻点增量及预计停车位置。
- 未通过时报告轴号、从 0 开始的点号、时间、实际值和限值，此时旧表尚未清除。时间为 `点号 × 0.002 秒`。停车估算采用 `p + v × |v| / (2d) + v × 0.002`，实际跟随误差和驱动延迟需现场测量。

源码入口见 [文件导入](../Wave/Legacy/WaveTrajectoryFile.cs) 和 [点位预检](../Wave/Legacy/WavePointValidator.cs)。

## ADS 下发与 PLC 确认

1. 上位机取得新非零序号，清旧接收状态，以本站身份写入点数、周期及序号。
2. `GVL_motion.aUpload` 有 21 段、每段四轴、每轴 100,000 点。应用以不超过 1,024 个标量点的批次写入，批次之间释放串行锁。四轴同段写完才提交段登记，每段等待 PLC 应答。
3. 全部段确认后请求统一拼表。只有点数、序号、站号及 `DataReady` 一致才可准备启动。控制权变化或失联使旧表失去启动资格。
4. PLC 执行首点定位和轨迹，持续监督控制权、心跳、轴反馈、限位和 MC 错误。上位机使用同一帧显示 PLC 取到的点数与百分比，首点显示为 1。实际停稳以反馈确认。

监控帧要求布局 4、164 字节，清表、下发和启动还要求接口行为版本 1。控制权和会话使用站点邮箱。写入或应答失败中止当前流程，不能把部分发送或 ADS 写入成功当成设备执行结果。正常人工停止与故障联停在 PLC 中分别处理。[点位下发](../Axis/PointUpload/AxisService.PointUpload.cs) · [控制权](ControlAuthorityRules.md) · [监控接口](PlcMonitoringContract.md)

## 参数从哪里来

仓库的 `FB_AxisConfig` 是虚拟轴调试的赋值入口。空闲且反馈有效时，它更新 `GVL_motion.aConfig`。手动控制、监控和轨迹使用这一份配置。运行期间按当前联锁保持既有参数。在线直接修改数组，后续空闲扫描可能恢复块内数值。

| 虚拟轴参数 | 当前源码值 |
| --- | ---: |
| 最小 / 最大位置 | -200 / 200 |
| 最大速度 | 200 |
| 最大加速度 | 12000 |
| 停车减速度 | 100 |
| 首点定位速度 | 10 |
| 到位容差 | 10 |

此前固定样例 `2222_2ms_327.66s.csv` 有 163,831 点，按旧速度/加速度限值 100/100，在第 270 号点首次因加速度约 -250 失败。200/12000 是那次虚拟轴调试参数。实机参数、单位、回原方式和许可接线以现场工程为准。[配置块](../PLC/TwinCAT_NB/axis_4/POUs/AxisConfig_轴配置/FB_AxisConfig.TcPOU) · [虚拟轴验收记录](OptimizationAcceptance.md)

## 遇到阻断时查什么

| 现象 | 优先检查 |
| --- | --- |
| 无法发送 | 本站授权、PLC 参数读取、四轴停稳和空闲。预检失败看首个超限位置 |
| 发送完成但无法开始 | 本次上传序号、站号、参数变化、互锁及报警 |
| 下发断在一段 | 操作日志中的段、轴、点范围和确认耗时 |
| 停止未确认 | 运行诊断中的实际停稳、退出状态及独立的停车错误。程序按既有流程暂停本站心跳，不重放运动请求 |
| 报告显示部分项目未评估 | 当前运行统计接入位置和速度，其他量按配置和反馈质量显示 |

离线执行记录、XAE 编译与在线验收分开查看。检查固定点表、停稳和退出等现场步骤见 [虚拟轴验收记录](OptimizationAcceptance.md)。日志与故障码的入口见 [运行诊断](RuntimeDiagnostics.md) 和 [运行实测统计](AxisRuntimeMonitoring.md)。
